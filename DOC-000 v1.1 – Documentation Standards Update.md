# DOC-000 v1.1 – Documentation Standards Update

## 1. Purpose

This document defines additional rules for maintaining documentation versions after the initial documentation set has been created.

The purpose of this update is to establish a controlled method for modifying existing documents when new architectural decisions affect previously defined specifications.

---

# 2. Document Versioning Rules

Existing documents shall not be rewritten completely when introducing compatible changes.

Instead, updates shall be published as separate versioned documents.

Example:

```text
DOC-101 - Scanner Module.md

DOC-101 v1.1 - Scanner Module Update.md
```

---

# 3. When to Create an Update Document

A version update document should be created when:

* a new core specification affects an existing module;
* previously defined behaviour requires clarification;
* compatibility rules are added;
* architectural dependencies change;
* implementation details require refinement.

---

# 4. Update Document Structure

Update documents should contain:

* reference to the original document;
* reason for update;
* changed sections;
* new requirements;
* compatibility information.

Example:

```text
Affected document:
DOC-101 – Scanner Module

Reason:
Introduction of DOC-012 – File Identity Specification

Changes:
Scanner shall use SHA512 as file identity.
```

---

# 5. Backward Compatibility

Unless explicitly stated otherwise:

* previous requirements remain valid;
* updates extend existing behaviour;
* modules should maintain compatibility with previous specifications.

---

# 6. Documentation Philosophy

Documentation should preserve project history.

The original document describes the state of the project at the time of creation.

Update documents describe the evolution of the system.
