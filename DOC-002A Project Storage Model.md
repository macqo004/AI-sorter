Project Storage Model

Project: AI Image Collection Management System

Document: DOC-002A

Version: 1.0

Status: Approved

Purpose: Storage Architecture Specification

1. Purpose

This document defines the physical storage model used throughout the project.

It specifies the relationship between the three working areas used by the system:

TODO
AI
FINAL

This document is referenced by all modules performing image analysis or automatic sorting.

2. Design Philosophy

The project separates image processing from the user's curated collection.

Artificial Intelligence never modifies the user's collection directly.

Every automatic operation is performed inside a dedicated working area.

The user remains the final authority regarding collection organisation.

3. Storage Areas

The project consists of three independent storage areas.

TODO

↓

AI

↓

FINAL

Each area has a different responsibility.

4. TODO

Purpose:

Incoming images.

TODO contains images that:

have never been analysed,
require re-analysis,
were manually returned by the user,
are waiting for processing.

TODO is considered the project's input queue.

Images may permanently remain inside TODO.

An empty TODO directory is not a project requirement.

5. AI

Purpose:

Automatically organised working collection.

AI contains images sorted exclusively by project modules.

The directory structure inside AI mirrors the structure defined by FINAL.

Images inside AI are proposals generated by the system.

The user may:

verify,
move,
reject,
reorganise,

without affecting the original collection.

The AI area may be completely regenerated at any time.

No user data should depend on its permanence.

6. FINAL

Purpose:

Approved collection.

FINAL represents the user's definitive collection.

FINAL is never modified automatically.

Only the user changes FINAL.

FINAL is considered the project's source of truth.

7. FINAL Structure

FINAL is not a single directory.

FINAL consists of multiple independent Collection Trees.

Current Collection Trees:

Anime

Monster Girls

Western Animation

Themes

Additional Collection Trees may be added in future versions.

8. Collection Definition

Collection Definition Wizard analyses only FINAL.

The generated Collection Definition describes:

Collection Trees,
Classification Boundaries,
hierarchy,
destination availability.

Neither TODO nor AI participate in Collection Definition generation.

9. AutoSort

AutoSort never moves images into FINAL.

Workflow:

TODO

↓

Analysis Modules

↓

Database

↓

AutoSort

↓

AI

FINAL remains unchanged.

10. User Workflow

Typical workflow:

New images

↓

TODO

↓

Analysis

↓

AI

↓

User verification

↓

Manual move to FINAL

The final transfer is always performed by the user.

11. Regeneration

AI is disposable.

If required:

Delete AI

↓

Run AutoSort

↓

Rebuild AI

The rebuilt structure is generated from:

database observations,
Collection Definition.

No information is obtained from previous AI content.

12. Relationship Between Areas

TODO

source of new work

AI

generated proposal

FINAL

approved collection

Information always flows toward FINAL.

FINAL never receives automatic modifications.

13. Source of Truth

The project contains multiple sources of information.

Physical collection structure:

FINAL

Image metadata:

Database

Working proposals:

AI

Incoming data:

TODO

Only FINAL defines the approved collection hierarchy.

14. Design Principles

The storage model follows these principles:

automatic processing never modifies FINAL;
AI is always reproducible;
TODO is expected to contain unresolved images;
FINAL defines collection structure;
Collection Definition is generated from FINAL;
AutoSort mirrors FINAL but never modifies it.
15. Future Extensions

Possible future additions:

multiple AI workspaces;
temporary review workspaces;
shared collections;
archived collections;
read-only Collection Trees.

The fundamental storage model remains unchanged.

16. Acceptance Criteria

The storage model is considered correctly implemented when:

TODO accepts new images;
AI contains automatically organised proposals;
FINAL is never modified automatically;
Collection Definition is generated exclusively from FINAL;
AutoSort mirrors FINAL structure inside AI;
deleting AI never affects FINAL.
