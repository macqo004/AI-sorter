# DOC-202 v1.1 – Database Maintenance Update

## 1. Purpose

This document updates DOC-202 – Database Maintenance to align database maintenance procedures with DOC-012 – File Identity Specification.

The original Database Maintenance rules remain valid unless explicitly modified below.

---

# 2. File Identity Compatibility

Database Maintenance shall follow DOC-012 rules regarding file identity.

The following principles apply:

* SHA512 represents file content identity;
* file_id is an internal database identifier;
* current_path represents the current file location.

---

# 3. Archived Records

Archived records shall follow DOC-012 status rules.

ARCHIVED records:

* are not automatically deleted;
* may be removed only by user action;
* should be backed up before permanent removal.

---

# 4. Database Rebuild Update

Database Rebuild shall recreate file records from the current collection.

Rebuild process:

1. Backup current database.
2. Create new database structure.
3. Load project configuration.
4. Scan configured directories.
5. Recreate file records.

After rebuild:

* file_id values may change;
* SHA512 values remain the file identity reference;
* current_path is recreated from existing files.

---

# 5. External References

External modules shall not permanently store references based only on file_id.

For long-term identification outside the current database instance:

```text
SHA512
```

shall be used.

Reason:

Database rebuild may generate new internal identifiers.

---

# 6. Integrity Verification

Database Integrity Check should verify:

* missing SHA512 values;
* duplicated file_id values;
* invalid ACTIVE records;
* missing current_path;
* broken relations with analysis results.

Results shall be reported according to DOC-011.

---

# 7. Review Queue Integration

Database Maintenance may create Review Queue entries according to DOC-013.

Examples:

* uncertain repair operations;
* damaged relations;
* inconsistent records.

No destructive repair shall be performed without user confirmation.
