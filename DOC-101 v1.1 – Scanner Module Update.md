# DOC-101 v1.1 – Scanner Module Update

## 1. Purpose

This document updates DOC-101 – Scanner Module to align Scanner behaviour with DOC-012 – File Identity Specification and DOC-013 – Review Queue Specification.

The original Scanner requirements remain valid unless explicitly modified below.

---

# 2. File Identity Integration

Scanner shall use DOC-012 rules when creating and updating file records.

Scanner shall:

* calculate SHA512 for supported files;
* create new file records when SHA512 does not exist;
* update existing records when only file location changes;
* preserve file identity during rename or move operations.

---

# 3. File Identification Rules

Scanner shall not use:

* filename;
* directory location;
* file_id alone;

as the primary identity of an image.

The primary identity is:

```text
SHA512
```

---

# 4. File Modification Handling

If a file exists in the database but its SHA512 changes:

Scanner shall treat it as a new file.

Required behaviour:

1. Existing record becomes ARCHIVED.
2. New record is created.
3. New file_id is assigned.
4. New SHA512 value is stored.
5. Analysis modules may process the new file.

Scanner shall not attempt to merge records based only on filename or location.

---

# 5. Missing Files

If a previously known file is no longer found:

Scanner shall not remove the database record.

Instead:

```text
status = ARCHIVED
```

according to DOC-012.

Permanent removal is handled by Database Maintenance.

---

# 6. SHA512 Calculation Errors

If Scanner cannot calculate SHA512:

Scanner shall:

* not create an ACTIVE record;
* log the problem according to DOC-011;
* optionally create a Review Queue entry according to DOC-013.

Scanner shall never create temporary or invalid hash values.

---

# 7. Review Queue Integration

Scanner may create Review Queue entries for:

* unreadable files;
* repeated processing failures;
* unexpected filesystem states.

Review Queue entries shall not automatically modify files or database records.

---

# 8. Database Relations

Scanner shall store:

* file_id;
* SHA512;
* current_path;

according to DOC-012.

Analysis modules shall reference file_id instead of file paths.
