7. Unknown Destinations

Analysis modules may recognise:

Universe
Character
Species
Theme

Recognition alone is insufficient.

AutoSort verifies that the destination exists inside Collection Definition.

If the destination does not exist:

no directory is created;
no automatic move is performed;
the database observation is preserved.

This allows future reprocessing after Collection Definition has been extended.

8. Regeneration

The AI workspace is disposable.

Deleting AI does not affect:

FINAL;
Collection Definition;
Database.

Running AutoSort again recreates AI using the latest database state.

9. User Verification

Images placed inside AI represent proposed organisation only.

The user decides whether to:

accept;
reject;
manually move;
reorganise.

Only the user modifies FINAL.

10. Design Principles

AutoSort follows these rules:

Database is the source of image classification.
Collection Definition is the source of directory structure.
FINAL is the source of approved organisation.
AI is a generated workspace.
FINAL is never modified automatically.
11. Implementation Requirements

AutoSort SHALL:

read Collection Definition;
create missing directories inside AI only;
organise images inside AI;
ignore destinations not defined in Collection Definition;
support complete regeneration of AI.

AutoSort SHALL NOT:

inspect FINAL during every execution;
modify FINAL;
infer new destinations;
create new Collection Tree branches automatically.
