1. Purpose

The Character Analysis module attempts to identify fictional characters depicted in an image.

Unlike Universe Analysis, Character Analysis does not analyse the complete set of supported characters.

Instead, it limits its search space using Universe candidates previously generated by Universe Analysis.

The module stores ranked Character candidates.

The module performs no file operations and makes no sorting decisions.

2. Responsibilities

The module SHALL:

identify candidate characters;
use Universe candidates to reduce search space;
rank candidate characters;
assign confidence values;
write candidate observations.

The module SHALL NOT:

identify real people;
determine image quality;
move files;
rename files;
modify directory structures.
3. Scope

The module recognises fictional characters belonging to previously identified universes.

Typical examples include:

Lumine
Furina
Nahida
Raiden Shogun
March 7th
Firefly

The supported character list is implementation-defined.

4. Input

The module reads:

Image
File
Scanner metadata
SHA-512
Universe Candidate Observations

The module shall only analyse universes whose confidence satisfies the configured threshold.

Default:

UniverseCandidateThreshold = 0.50

This value shall be configurable.

5. Output

The module writes Character Candidate Observations.

Each candidate contains:

ImageID
ModuleID
Candidate
Confidence
Rank
Timestamp

Multiple candidates may be stored.

6. Candidate Selection

Only candidates whose confidence satisfies the configured storage threshold shall be written.

Default:

CharacterStoreThreshold = 0.50

Candidates shall be ranked by confidence.

7. Character Assignment Threshold

Automatic character assignment is independent from candidate storage.

Default:

CharacterAssignmentThreshold = 0.75

If the highest-ranked candidate does not reach this threshold:

no automatic character assignment shall occur;
the image shall remain assigned only to its Universe.

Candidate observations shall still be stored if they satisfy the storage threshold.

8. Definitions
Character

A fictional individual belonging to a supported universe.

Character Candidate

A possible character assignment associated with a confidence score.

Character candidates are suggestions rather than final decisions.

Automatic Assignment

Automatic placement of an image into a character-specific directory.

Automatic assignment requires the assignment threshold to be satisfied.

9. Processing Rules

Each SHA-512 shall be analysed only once.

Existing Character Candidate Observations shall prevent unnecessary reprocessing.

If SHA-512 changes, previous Character Candidates become obsolete.

10. Database Access

The module reads:

Image
File
Module
Observation
Universe Candidate Observations

The module writes:

Character Candidate Observations

The module shall never modify observations created by other modules.

11. Scan Scope

The module supports configurable scan scope.

Typical usage:

Genshin collection;
Honkai collection;
user-selected directory;
complete Anime collection.

The module shall never require processing of unrelated collections.

12. Performance Requirements

The module shall support batch processing.

Search space shall be reduced using Universe Candidates.

The implementation shall avoid comparing against characters belonging to unrelated universes.

13. Threading

Parallel execution shall be supported.

Worker thread count shall be configurable.

14. Error Handling

If analysis fails:

processing continues;
the error is logged;
incomplete Character Candidate lists shall not be stored.

16. Interaction with Other Modules

The module depends on:

Scanner
Universe Analysis

It may optionally consume observations from other modules.

The module shall never invoke another module directly.

17. Design Philosophy

The Character Analysis module is intended to refine Universe classification.

Failure to identify a character shall never invalidate Universe classification.

Character identification is considered an optional refinement layer.

When confidence is insufficient for automatic assignment, the image remains organised at Universe level.

This behaviour is intentional.

18. Future Extensions

Version 1 intentionally excludes:

multiple-character relationships;
background character identification;
pose recognition;
facial expression analysis;
costume variants;
skin recognition;
alternate outfits;
duplicate character detection.

These capabilities may be implemented by future modules.

19. Acceptance Criteria

The module shall be considered complete when it can:

identify candidate characters;
utilise Universe Candidates;
reduce search space;
rank character candidates;
distinguish between storage and automatic assignment thresholds;
leave uncertain images assigned only to Universe level;
operate efficiently on large image collections.
